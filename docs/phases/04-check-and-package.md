# Phase 4 — Check and package

## Entry and required inputs
`start phase 4`: read `AGENTS.md`, brief, status, master plan, this file, Phase 3 document, `docs/environment.md`, `docs/artwork.md`, and actual production outputs.

Starting this phase does NOT authorize build/test/review/publish commands. Read current instructions and record exact permitted activities; previous-phase authorization does not carry forward.

## Independent preparation
- [ ] Prepare `docs/release-checks.md` with cases below marked **not performed**. Inventory known handoff blockers without an unsolicited code review.
- [ ] Draft `docs/install.md` for unpackaged folder distribution. Record actual architecture/runtime requirements from project settings; separate proposed instructions from demonstrated installation.
- [ ] If authorization is missing, ask one focused question for the needed build/check activity after independent preparation. Do not invoke commands indirectly. Keep phase pending if required work is not authorized.

## Execute only within current authorization
- [ ] Build release configuration, record exact command/version/result/artifact, and address concrete failures within scope.
- [ ] Automated tests only if authorized: prioritize state corruption/interrupted save, validation, placement. Code review only if explicitly requested.
- [ ] Authorized manual walkthrough: first launch; default/long goal edits; Save/Cancel; quit/relaunch persistence; duplicate launch; dragging; removed screens; 100/125/150/200% scaling; other apps covering it; taskbar recovery; Quit; disabled transparency; high contrast; reduced motion. Record actual results or omissions. Win+D survival is not required.
- [ ] Inspect actual-size composition, especially centered text over mountains. Record accepted native differences instead of claiming pixel-identical browser glass.
- [ ] Confirm artwork provenance before redistribution.
- [ ] With build/publish authorization, produce local unpackaged release folder/ZIP with required runtime files or precise prerequisites. Verify launch from it when authorized. No store uploads, system-startup changes, or certificate installation.
- [ ] Finalize install/removal instructions from observed behavior. Removing app binaries should not silently delete local goal data; explain separate optional removal.
- [ ] Update status once with checks/omissions, artifact location, limits, and completion/pending state.

## Deliverables and stop
Actual distributable, install guide, artwork record, release-check record. If essential builds/checks are absent, report **release pending** with exact remaining work, not verified/installation-ready. Stop after this phase; timer/Apple work requires separate scope.
