# Phase 3 — Visual finish

## Entry and required inputs
`start phase 3`: read `AGENTS.md`, brief, status, master plan, this file, Phase 2 document, `docs/environment.md`, native source, and centered HTML preview. Resume actual Phase 2 state; do not assume a successful build.

## Steps
- [ ] Carry forward feasibility limitations. If a dependency prevents meaningful visual work, explain it without claiming an unbuilt shell was verified.
- [ ] Clear provisional artwork provenance/redistribution terms or replace within authorized scope. Record source/permission in `docs/artwork.md`; do not assume unknown images are cleared for shipping.
- [ ] Implement approved palette, crop, frost, rim light, depth, typography, and corners in widget/resources. Prefer a clean supported native shape if exact corners are impractical; disclose the visual difference.
- [ ] Center goal vertically/horizontally with centered lines. Preserve line breaks, shrink within size 39–23, and reject edits that still overflow instead of clipping.
- [ ] Keep enough frost behind lettering for contrast over mountains. Preserve composition while inactive/without transparency. No idle animation.
- [ ] Refine editor/menu, keyboard focus, hit areas, Save/Cancel and error messages. Respect high contrast/reduced motion. No prototype toolbar/caption in the app.
- [ ] If allowed and an executable exists, manually inspect display scaling, short/long goals, light/dark surroundings, inactive appearance, and fallback. New builds/tests/review require this phase's explicit authorization.
- [ ] Update status once with files, art provenance, actual observations, omitted checks, unresolved fidelity issues. Do not invent user acceptance.

## Deliverables and stop
Refined native UI, cleared artwork and record, handoff. Distinguish styling implemented from appearance observed. Stop before Phase 4 and packaging.
